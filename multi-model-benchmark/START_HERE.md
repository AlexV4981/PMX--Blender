# Start here — agent setup or manual setup

Both routes use the **same commands**, create the **same folders**, and can be switched at any time. **You download ALL animation packs and VMD samples yourself.** Neither route downloads AI model weights or motion assets.

Requirements: Git, Python 3.10+, the Multi-Model-PMX-Benchmark branch; Docker/Blender for actual isolated evaluation and existing local Ollama for model proposals. An agent must ask before installing dependencies or obtaining a Blender image.

## A. Agent-assisted setup

Give a coding agent with local terminal access:

> Use https://github.com/AlexV4981/PMX--Blender/tree/Multi-Model-PMX-Benchmark. Follow multi-model-benchmark/AGENTS.md. Check out that branch; run python multi-model-benchmark/setup.py prepare. Verify unit tests, fixtures, Python/Git, and existing Docker/Ollama. Seek permission before software or Docker-image installs. Do NOT download animations, VMDs, or AI models. Prepare the manual download inbox and report what is missing. When I have placed the files there, import with python multi-model-benchmark/assets.py import-inbox and report hash receipts. Only run a real Blender smoke test if a pinned image is installed; never claim unrun steps passed. Preserve other branches and repositories.

The agent can stop after preparation. The folders remain on disk; proceed with the manual commands below whenever you choose.

## B. Manual setup — exactly the same operations

For a new clone:

~~~bash
git clone --branch Multi-Model-PMX-Benchmark https://github.com/AlexV4981/PMX--Blender.git
cd PMX--Blender
python multi-model-benchmark/setup.py prepare
~~~

For an existing clone:

~~~bash
git switch Multi-Model-PMX-Benchmark
python multi-model-benchmark/setup.py prepare
~~~

Want to perform each agent setup step manually rather than run prepare?

~~~bash
python multi-model-benchmark/setup.py init
python -m unittest discover -s multi-model-benchmark/tests -v
python astra-qwen-weight-lab/fixtures.py generate
python multi-model-benchmark/setup.py status
~~~

The setup only creates folders, runs unit tests, and generates synthetic fixtures; **it does not run Blender, silently install programs, download content, or qualify a model**. Fix failures before moving on.

## Manual animation inbox (generated by either route)

~~~text
multi-model-benchmark/
  setup.py
  assets.py
  data/                               # ignored by Git
    animation-assets/
      manual-inbox/                   # USER puts downloads here
        README.txt                    # source links and commands

        quaternius-ual2/              # one Standard .zip
        mmd-tools-vmd-smoke/          # one .vmd
        other-vmd/                    # optional unreviewed motions
        other-blender/                # optional unreviewed motions
      downloads/                      # original imported copies
      pmx-vmd/                        # validated VMD
      blender-native/                 # extracted FBX/GLB/BVH
      retargeted/                     # derivative work; not downloaded
      receipts/                       # SHA-256/provenance
    runs/
    reports/
~~~

**You personally obtain:** [Quaternius UAL1 Standard ZIP](https://quaternius.itch.io/universal-animation-library), [Quaternius UAL2 Standard ZIP](https://quaternius.itch.io/universal-animation-library-2), and the [MMD Tools test.vmd sample (download raw)](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/samples/vmd/test.vmd). Put exactly one matching archive/file into its named manual-inbox folder. The importer accepts original filenames. The Quaternius packs are publisher-hosted free Standard archives; they do not have assumed stable direct URLs.

**After you download** (either you or the agent can do all of these steps):

~~~bash
python multi-model-benchmark/assets.py import-inbox
python multi-model-benchmark/assets.py list
python multi-model-benchmark/setup.py status
~~~

The importer never fetches from the internet. Missing assets are shown as WAITING; ambiguous files fail. Once all three are present, optionally run:

~~~bash
python multi-model-benchmark/assets.py verify
~~~

VMD here is only for parser/format smoke, not full-body motion qualification. Real retargeting and licensed source-model fixtures remain separate tasks.

## Both paths: check existing software and prove real Blender isolation

~~~bash
docker image ls --digests
ollama list
~~~

Install/approve an updated Blender image if needed and obtain its **actual registry digest** (not merely the local image ID). When an image is ready:

~~~bash
python multi-model-benchmark/smoke/run_stage03_smoke.py --image 'blender@sha256:REPLACE_WITH_ACTUAL_DIGEST'
~~~

Only accept **correct=pass** and **wrong=fail**, with independent isolated builder/verifier execution. This has **not yet been run on your laptop**. The authored smoke does not require any animation pack downloads, so you can run it before obtaining those assets.

## Both paths: start with one already-installed AI model

~~~bash
python multi-model-benchmark/runner.py inspect --model YOUR_INSTALLED_TAG
python multi-model-benchmark/runner.py run --model YOUR_INSTALLED_TAG --stage 03 --cases astra-qwen-weight-lab/data/fixtures/cases.jsonl --out multi-model-benchmark/data/your-model-stage03-lap00.jsonl
~~~

These commands **only generate code proposals**. For actual hash-bound Blender evaluation, use [HARDENING_v2_README.md](HARDENING_v2_README.md). No pass or production qualification is implied by a successful Ollama reply. Never execute model-generated Python outside the isolated builder or on an approved model file.

At every handoff, run python multi-model-benchmark/setup.py status. Agent and manual setups are completely interchangeable; both must preserve the inbox and evidence.
