# Opt-in trial protocol

## Baseline and budget
Use a fresh authorized model or disposable duplicate of a frozen checkpoint. Record V4.2 SHA, model/input hashes, fixture versions, Blender/device settings and agent model/effort. Compare V4.2 alone with V4.2 plus these procedures under comparable starting conditions; use separate context and writable directories. Keep protected assets read-only. Predeclare issue/stage/run budgets and success measures. Reserve work in the existing journal. Stop on exhaustion; do not add a second journal or reopen completed stages to exercise this pilot.

## Physics reset test
Select a known genuinely articulated fixture A and contrasting fixture B, both relevant to the affected category. Declare timebase, frames, category settings, rest state, pre-roll/reset recipe, tolerances and outputs before testing. Compare at least these histories: fresh A, fresh B, fresh A repeated, fresh B repeated, A then reset then B, B then reset then A. Keep same target inputs and sequential evaluation; separately record cached playback. For each target compare matched evaluated positions, contacts, constraints, settling and invalid state against its fresh control using existing qualified Stage 08 tools. Include positive control for a known reset defect when available. If baseline repeats differ, classify instability/inconclusive before blaming an edit. Neutral-only clips, placeholders and unmeasured results cannot pass. This is a procedure, not a Blender reset implementation. Run only affected category/fixture first; escalate wider coverage based on evidence. Preserve exact protected behavior when claiming lossless optimization.

## Knowledge reuse
Start with search of cases.json and private verified cases. Candidate records are hypotheses only. To promote a case, attach an immutable evidence hash, exact reproduced fault, distinguishing test, protected-output checks, applicability and explicit exclusions, observed repair result and relevant environment/dependency versions. Keep private evidence outside public repository. A successful repair on one model does not prove transfer to others. Test applicability on the next model before reuse. Do not automatically edit a model from a case.

## Agent behavior trial
Use scenarios.json as a set of independent simulated situations. For each scenario provide the same starting artifacts to both agents (V4.2 baseline, pilot). Where possible instrument attempted writes, reservations and actual tool calls. Freeze the scenario's expected and forbidden behaviors; evaluate against observed actions and evidence with an independent reviewer. Mark pass/fail/inconclusive with evidence, not self-assessment. Repeat only if the authorized budget permits. No human approval may be fabricated. Keep behavioral results separate from utility tests and real Blender qualification.

## Asset permissions
Record creator, exact source, license evidence, and independent statuses for private use, modification, redistribution, and training. Allowed requires evidence; unknown does not confer permission. Restrict unauthorized downstream activities. No inference of training rights from download availability.

## Decision
Compare completion and protected quality first. Then compare actual usage if available, tool-call counts, repeated implementation attempts, subprocess times, context sizes and human interventions. Record all failures and overhead introduced by the pilot. Do not adopt a mechanism if it creates more work without demonstrated benefit. Proposed further phases require separate approval. No relaxed FPS, fidelity, native physics or existing gate requirements.
