# Bounded execution — V4 pilot

Based on the November 27 audit case study: 466 recorded execution jobs, 15.52 cumulative subprocess hours, 734 working scripts, about 500 KB of active handoff text, and six r36–r41 batches without retained improvement. These are workload observations, not measured AI tokens.

Use the separately reviewed Sprawling Instructor skill (or an equivalent persistent journal) for each experiment and diagnosis. Set run/stage/issue budgets with the human at setup. Reserve before implementation; rollback, session restart, renamed hypothesis and ownership transfer never reset counters. No unlimited extensions. A blocked attempt stops the issue, not required verification of other issues. One writer, one Blender workload. Record exact protected baseline, issue ID, hypothesis, distinguishing test, rollback and acceptance criterion. Final qualification is not an optional experiment.

Context: AGENTS <=8 KB and RESUME-HERE <=12 KB proposed limits; archive full history, keep one authoritative current state. Plain-language one-screen summary, engineering report and machine evidence remain separate. Do not repeatedly regenerate common resource guards, fixture readers, comparisons and parsers. Reuse verified helpers and validate harnesses with known good/bad controls. Capture tool calls, subprocess time, measured/estimated usage separately where available; do not equate subprocess hours with quota.

Qualification ladder: static preflight; focused smoke test; viability (reject weak performance candidates); affected regressions; full selected-package checks. At stages 01–07 record a cheap diagnostic cost line when a valid harness is available, otherwise unknown. Do not optimize prematurely or require expensive full viewport suites per stage.

Debt: use pipeline.py debt RUN add ID --source-stage 08 --owner 08 --severity major --description 'observed fault' --evidence audit/file.json. Use debt RUN list; close requires evidence and actual result; accept requires actual human identity/statement with exact scope. Disposition does not mutate a required check status. Major/blocker debt blocks 08P entry and 09 entry/submission. CLI cannot prove evidence semantics or authenticate approvals. This pilot retains immutable approved stages; repair after approval needs an authorized separate lineage and fresh qualification, not an invented override.

Performance: profile before implementation; only use the Amdahl upper bound when a defensible serial critical-path fraction exists. Do not sum overlapping costs. Default retain the existing 2%/2×span screen where relevant, calibrate protocol at 00; no automatic promotion from a short pilot. Optional playback mode is not mandatory and must independently pass relevant tests. No cached-as-live or alternate-engine substitution. No automatic accepted-gap gate; unresolved performance remains blocked until an explicit scoped requirement decision is implemented in a qualified policy. This pilot does not implement a policy-amendment command.

Equivalence: protect unchanged source data, visible outputs, controls and physical behavior exactly for lossless claims; permit scoped hidden implementation changes with protected-output tests. Corrective repair requires predetermined functional tolerances; artistic change human review. Never weaken tolerance post-failure. Dependency reuse requires matching actual component, fixture, harness and environment identities plus evidence hashes and causal justification; unknown dependencies rerun. The helper compares declared hashes, not Blender semantic completeness.

Historical replay: r37/r38 reject then bounded renewed diagnosis, r39 reject then stop; r41 failed precheck must not spawn blind retries; neutral fixture and placeholder arrays block coverage; debt never turns a failed check into pass; 09 cannot register changed bytes; historical V3 ledger must be rejected by V4. These are pilot regression scenarios, not reproduced Blender outcomes.
