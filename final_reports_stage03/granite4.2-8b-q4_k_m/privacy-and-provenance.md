# Privacy and provenance

This public export follows the repository model-report standard and v2.1 seven-section generator. Numbers and original result categories derive from locally validated ledger events and hash-addressed evidence. Narrative interpretations are separately attributed; sanitization does not change scores, verdict categories, thresholds, missing measurements or history.

Transformations to the generated report: replace its experiment-only title with the model title; replace the machine/environment row with an explicit public allowlist; redirect raw evidence-path references to public case verdict rows; clarify one preparation-only authorization sentence using the subsequent observed launch instruction; append links to the analysis attachments. Score/count/interval tables and capability rows are unchanged. Formal best_lap_id remains null because no validation split exists.

Published allowlist: model tag/digest/quantization, selected numeric architecture metadata, native template/controller hashes, experiment and synthetic fixture IDs, exact synthetic prompts/settings, per-case outcomes and timing/token metrics, safe evaluator notes, completed-response counts, repetition-boundary counts, test/probe summaries and public checksums. Original synthetic candidate/response hashes identify evidence without publishing source content.

Excluded: absolute local or network paths, personal/machine identifiers, OS/hardware fingerprints, credentials, raw model code and reasoning, raw partial streams, continuation-token arrays, raw logs/stack traces, native Modelfile, full tokenizer metadata, private assets, original private asset/contract fingerprints, unreleased reference implementation and non-Stage03 results. Resource observations are summarized without publishing device identity or traces. No private real-character data was used in Granite's ten laps.

Verification includes the full ledger/artifact check, all200 reconstructed prompt hashes, all186 actual request bodies, exact lap4-to8/lap8-to9/lap9-to10 comparisons, per-lap status/count reconciliation, unchanged model-layer receipts, seven-section structure, relative links and export checksums. Public verdict rows are allowlisted derivatives, not replacements for the private original evidence. A checksum verifies bytes, not independent execution attestation. The operator/host can influence evidence; no claim of cryptographic immunity to a host administrator is made.
